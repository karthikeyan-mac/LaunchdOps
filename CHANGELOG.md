# Changelog

## 1.0 (in development)

- Release preparation: the README lists every keyboard shortcut, Project ▸ Show Plist XML… ends with an ellipsis because it opens a sheet, the Delete key removes a focused payload file, and the error for a project from a newer format tells you to update LaunchdOps. A test covers the newer-format error.
- Fixed: `sudo ./check.sh --collect` made its folder in `/private/tmp` readable only by root, so Finder couldn't open it. The folder and its files now belong to the admin who ran `sudo` (from `SUDO_UID`) and stay mode 700, so other users still can't read the logs.
- Summary behaviour notes from `launchd.plist(5)`: Repeats is also skipped while the job runs and is independent of calendar schedules, calendar runs missed in sleep become one run on wake, conditional Keep Alive explains that any matching condition keeps the job alive and starts it at load, Minimum Gap names the 10-second default, Stop Timeout explains SIGTERM then SIGKILL (and that zero waits forever), Priority points to Process Type, and log files say how they are created.
- Summary notes follow `launchd.plist(5)` more closely: `UserName`, `GroupName` and `InitGroups` are flagged as ignored for agents, `LimitLoadToSessionType` as having no effect on daemons, the Disabled note says `launchctl enable` or `disable` overrides the plist (the state is kept outside it), and Other Keys explains obsolete or special keys (`OnDemand`, `ServiceIPC`, `TimeOut`, `LimitLoadToHosts`, `LimitLoadFromHosts`, `EnablePressuredExit`, `RootDirectory`, `KeepAlive ▸ NetworkState`, `KeepAlive ▸ OtherJobEnabled`).
- New app icon: a Cron Grid mark (a 5 × 5 dot calendar with the next run lit in amber) made as original artwork, built as a layered Icon Composer icon (`LaunchdOps/LaunchdOps.icon`: background colour plus three SVG layers). Xcode renders the macOS 15 images from it. The old asset-catalog `AppIcon` set and the earlier SF Symbol artwork are gone.
- UI review fixes: Help ▸ Notarize now points to the Notarizing toolbar button for cancelling (it named a Cancel button on the Export tab that no longer exists). VoiceOver reads each file in the Export tab's Output list (it read only "Files that will be exported"), and the Remove button in Additional Keys is its own element again. An older output preview can no longer replace a newer one with its error. The Summary headline is built from styled text instead of parsed Markdown, so program names with backticks, asterisks or underscores show as typed. Settings uses the `Tab` API, the window's alerts, dialogs and Rename sheet use item-based presentation, and the validation popover no longer has a fixed height. User-facing text that was built from plain `String` values or joined with `+` is now localizable.
- The Xcode project sets `ARCHS = $(ARCHS_STANDARD)` and, for Release, `ONLY_ACTIVE_ARCH = NO` explicitly, so Release builds and archives are always universal (arm64 and x86_64). Debug still builds only the Mac's own architecture, for speed.
- Fixed: with no job selected (for example after deleting every job), the toolbar reported "Enter a reverse-DNS package identifier" from an empty placeholder project. Nothing is validated without a selected job, and the validation status is hidden until one is selected.
- General ▸ Program: with Program set and no arguments yet, Add Argument puts the program path in the first row (the process name, ProgramArguments[0]) and adds an empty row for the first option, so options like `--silent` land where the program receives them. The Arguments ⓘ explains that options start on the second row, and empty rows show what belongs there (Process name, or Option, for example --silent). Empty argument rows are left out of the exported plist, the Summary and validation.
- New warning `program.argv0-option`: when Program is set and the first argument starts with `-` (for example Program plus ProgramArguments `["--silent"]`), launchd passes that option as the process name and the program never receives it. The Summary's command line note says so too.
- Summary ▸ Program & Arguments shows the full command line as you would type it in Terminal (arguments with spaces or shell characters are quoted, so it can be copied and run by hand), with a note that launchd runs it directly, not through a shell, and the process name when Program and ProgramArguments[0] differ. A job that runs `sh`, `bash` or `zsh` with `-c` also shows the script. The separate Program and Argument rows, which repeated the General tab, are gone.
- The sidebar has a third group, User Launch Agents, for agents that install in ~/Library/LaunchAgents; Launch Agents now lists only agents for all users. Empty groups stay hidden.
- The Notarizing toolbar button is filled with the accent color, so a running notarization is easy to spot.
- Payloads are for the script or tool a job runs: General ▸ Program's footer and the Payload ⓘ say so, and suggest deploying apps and large software separately and referencing their installed path. New rule `payload.total-size`: a warning when a job's payload files add up to more than 200 MB (editing, exporting and notarizing get slow, because payloads are held in memory) and an error over 1 GB. Clicking a payload issue now opens General, where payload files are edited (it opened Export).
- Duplicate Job (Project menu, ⌘D, and Duplicate in the sidebar's context menu): copies every key, payload file and export setting into a new job labelled `<label>.copy` (then `.copy2`, `.copy3`…). The copy gets its own package identifier (following the new label), task type and profile UUIDs, so installing it never replaces the original. Undoable.
- New Job from Clipboard (Project menu): creates a job from plist XML on the clipboard, keeping keys LaunchdOps doesn't edit, as file import does. A plist with LimitLoadToSessionType becomes a Launch Agent (All Users), anything else a Launch Daemon; change it on General. Text that isn't a launchd plist, has no Label or is over 1 MB shows an error instead.
- `check.sh --collect` also records each job's `launchctl print-disabled` state and the last 200 lines of its StandardOutPath and StandardErrorPath files (only the paths the job defines, read only).
- Notarization progress is easier to follow: a Notarizing button with a spinner sits in the toolbar on every tab while Apple checks the package (it was a line of small text at the bottom of the Export tab). Click it for the steps (upload, Apple's check, staple) with the current one highlighted, the elapsed time and Cancel Notarization. The Dock icon bounces when notarization finishes while LaunchdOps is in the background.
- Settings ▸ Signing: each ⓘ now explains how to set the option up, step by step, with a link to Apple's instructions: getting a Developer ID Installer certificate (Account Holder only), what to do when an identity is missing, what notarization does, creating the App Store Connect API key (team key with the Developer role, or an individual key) and getting a certificate for signing the profile.
- Simpler export: one flat folder with the package, the Managed Login Items profile, a reference copy of each plist, `check.sh`, `uninstall.sh` and `README.md` (no `launchd/`, `package/`, `profiles/`, `scripts/` or `verification/` folders; Build Script output keeps `package/` and DDM keeps `ddm/`). `check.sh` replaces verify.sh, test.sh and diagnose.sh: with no options it prints the status line for any MDM's inventory (`--result` or `RESULT_TAGS=true` for `<result>` tags), `--details [--run]` tests an installed copy and `--collect` gathers diagnostics. Fixed: the status line now includes User Launch Agents (verify.sh printed only the version for them), and reports `program-missing` when a job's program isn't on the Mac. VALIDATION.md and `ddm/hashes.txt` are now sections of the README, and the Export tab's Fleet Verification row is part of Scripts. Update inventory scripts that pointed at `verification/verify.sh` to use `check.sh`.
- User Launch Agents are now installed by the package instead of being left out (the package was empty when a project had only a user agent and no payload). The package stages the plist in `/Library/Application Support/LaunchdOps/UserAgents/`; postinstall copies it into the logged-in user's `~/Library/LaunchAgents` (the owner of `/dev/console`), running as that user so root never writes into a folder the user controls, and loads it in their session. With nobody logged in it installs nothing and logs why. Disabled jobs are copied but not loaded. preinstall stops the agent, uninstall.sh removes the copy from every local account and the staged plist, and test.sh and diagnose.sh check the staged plist. Other users don't get the agent; the Note on the job and the README say so.
- Fixed (code review): cancelling the save panel now forgets the export it was for, so a later Export Plist… can no longer notarize an earlier package. The newsyslog rule is now removed by preinstall before every install (the package puts it back if the new version still rotates logs) and always by uninstall.sh, so turning Rotate Logs off or turning on Keep Alive in a later version no longer leaves the old rule rotating a log the job holds open. Signing a package uses the private key twice instead of three times (one fewer keychain prompt): the archive is laid out with the expected CMS signature size and laid out again only if the signature comes out a different size; the size is remembered for the rest of the session.
- Removed Notarize Package…, Staple Package… and Cancel Notarization from the Project menu. Notarization is set in Settings ▸ Signing (Notarize After Export) and runs after each export, which also staples the ticket; Cancel Notarization in the Export action bar or the toolbar progress menu stops it. For a package notarized elsewhere, the alert and README give the `xcrun stapler staple` command.
- UX (external review): the Export tab starts with a Readiness checklist (validation, package signing, notarization or DDM hosting, profile, payload) with a ready, review or fix icon on each row. Every sidebar row shows its job's error or warning icon, not just the selected one; results are cached, so only changed jobs are validated again. Clicking an issue opens the tab where it is fixed. Issue rows and severity help tags say what each level means ("Error: must fix", "Warning: review before deploying", "Note: recommendation"). With no jobs, the window shows Create Your First Launchd Job with New Job… and Import Launchd Plists…. Choose… for Program now offers Add to Payload (default) or Reference Existing Path, and explains when to reference the path.
- Security hardening (external review): one validator, `SafeInstallPath`, now checks every payload name, payload destination, package install path and log folder, and accepts only canonical paths (no `//`, `.` or `..` folders, names starting with a dot, control characters, or names over 255 bytes). Unsafe labels, package identifiers, task types, payload names and destinations, and group- or world-writable payloads are now blocking issues: Export shows "Fix These Before Exporting" and doesn't offer Export Anyway, and the exporter refuses them too. Opening a `.launchdops` file rejects duplicate job or payload IDs and file modes outside 0–7777. New note `program.location-unverified` when a root daemon's program isn't in a macOS system folder and isn't installed by the package, because LaunchdOps can't check who can write to it. The notarization key is saved in the data protection keychain (this Mac only, available while unlocked) when the build is entitled to it, otherwise in the login keychain; it is never synchronized, and a key found in the login keychain moves over when possible. New tests cover hostile project files.
- About LaunchdOps shows "Developed by Karthikeyan Marappan" (linked to https://www.linkedin.com/in/bewithkarthi/) and "Copyright © 2026 Karthikeyan Marappan. All rights reserved." The credit comes from `LaunchdOps/Credits.rtf`, the copyright from `NSHumanReadableCopyright`.
- Logging: shared loggers with one category per area (App, Library, Export, Signing, Notarization, Stapling). New entries for app launch (version and macOS), each save and delete, each export (settings, issue counts, file count, size and time), signing identity use (private), each notarization step (submission ID, upload size and time, retries, final status and duration) and stapling. Help ▸ Open Log in Console is now Help ▸ View Logs, and its note lists the steps as a numbered list, including filtering by category.
- Clear DDM deployment instructions. Help ▸ LaunchdOps Help has a Deploy with DDM topic (requirements, six steps, updating, when to use a package instead). The exported README's DDM section is reorganized into What you need (an MDM that can send declarations, supervised Macs, macOS 15+), Why use it, What's in this folder, Step 1 Host the assets, Step 2 Give it to your MDM, Step 3 Check a Mac, Updating, Removing and Troubleshooting.
- DDM mode no longer blocks a program outside the background task's folder: Apple's declaration allows any path. `ddm.program-location` is now a warning that explains the program isn't delivered by the task or tamper-resistant, offers both fixes (install it another way, or use a payload file), and also checks a script passed to a macOS program such as `/bin/zsh`.
- Issues can be copied: each issue has Copy in its context menu, the issues on each tab are selectable text, and the status popover and the Export tab's Validation list have Copy All Issues. Help ▸ Open Log in Console opens Console with the search for LaunchdOps's log messages (`subsystem:com.karthikmac.LaunchdOps`) on the clipboard.
- Export ▸ Deploy As greys out DDM Background Task for a User Launch Agent and says why: background tasks install daemons and agents for all users, not in ~/Library.
- DDM background tasks, checked against SupportCompanion's helper deployment notes: new warning `ddm.keepalive` when a background-task job uses Keep Alive (the Mac restarts the task on configuration updates, and launchd relaunching it then has failed with "Operation already in progress"; use Run at Load). The README now explains that the task's files can't be changed even by root and the job can't be unloaded or disabled, and how to update (re-host, send new declarations; `ServerToken` follows the file hashes).
- New Summary tab, last in the toolbar (⌘4), shows what the selected job's plist says: a one-sentence headline, then only the keys the plist contains, grouped as General, Program & Arguments, Schedule, Keep Alive & Restart, Logging, Environment & Limits and Other Keys (keys LaunchdOps doesn't edit); unset options are left out. Each row gives a plain name with the plist key it comes from (for example `ProgramArguments[0]`), the value, and a short note where launchd's behaviour is surprising (a Start Interval run is skipped while the Mac sleeps; a calendar run happens once on wake). Environment variable values are never shown. Each section links to the tab that edits it.
- Security: the exporter now refuses, even after Export Anyway, any label, package identifier, task type or payload name or destination that isn't safe in file paths and root install scripts, and says what to fix. The postinstall comment for a disabled job no longer contains the label. This closes a root command injection through an imported plist's label and a path escape in diagnose.sh.
- Fixed (code review): a label edit that ends after selecting another job now retires the old label on the job that was renamed, not the newly selected one; an export marks the exported job's labels as published even if the selection changed while it ran; clicking in and out of a field without changing anything no longer adds an empty undo step or a save; the README's profile step stays item 4 of the Deploy list.
- Checked generated output against Apple's schemas and deployment guide, newsyslog.conf(5) and MDM vendor documentation. Fixed: the log rotation rule no longer signals syslogd (`N` flag), and rotation applies only to jobs that start and exit, because a job that keeps running holds its log open (Rotate Logs is hidden for those, and a new warning suggests the unified log). The README now states Apple's signing requirement for MDM-installed packages, macOS 26 declarative app management and macOS 27 uninstall tracking, and that Managed Login Items needs user-approved MDM; the per-tool table is corrected and adds Addigy, Kandji and Mosyle rows.
- Output works with any MDM: one `verification/verify.sh` replaces the Jamf Pro extension attribute and Intune custom attribute scripts (add `--result`, or set `RESULT_TAGS=true` where the tool can't pass arguments, for `<result>` tags). The README's Deploy section has one set of steps for any MDM, then a table of where to find each feature in Jamf Pro, Intune, Workspace ONE, Kandji/Mosyle/Addigy and Munki; the DDM section lists the fields with their declaration keys and notes Jamf Pro Blueprints and raw declarations.
- DDM background tasks, checked against Der Flounder's Jamf Pro Blueprints walkthrough (2025-06-10): the README lists every Blueprints field with its value (task type, description, executable ZIP and each launchd plist with file, SHA-256 and content type), shows how to check the server's `Content-Type` with `curl -sI` and a hash with `shasum -a 256`, and how to confirm the task on a Mac under the enrollment profile's Device Declarations. New warning `ddm.task-type-label` when the task type differs from the daemon label, which Blueprints requires.
- With a Label Prefix set, the New Job sheet starts with just the prefix (for example `com.karthikmac.`) and the cursor after it; Create stays disabled until a name follows the dot or when another job already uses the label.
- The deployment README's notarization text follows Settings ▸ Signing: with Notarize After Export on it says LaunchdOps notarizes and staples the package (and how to confirm it) instead of listing notarytool steps; an unsigned package explains that it must be signed first.
- The sidebar shows each job's Project Name (Export tab) when set, with its label underneath, so renaming on the Export tab updates the sidebar and window title. Rename… in the sidebar's context menu and the Project menu edits the same name; leave it empty to use the label. Undoable.
- Logging: install, upgrade and removal scripts record each step in the unified log (`log show --predicate 'process == "logger" AND eventMessage BEGINSWITH "LaunchdOps:"'`) as well as `/var/log/install.log`, and diagnose.sh collects them. Settings ▸ General ▸ Log Folder gives new daemons `<folder>/<label>.log` and `.error.log`; the install script creates missing log folders. Options ▸ Logging ▸ Rotate Logs installs a newsyslog rule (5 compressed copies, 10 MB each) that uninstall.sh removes; the validator warns when a long-running daemon's log is never rotated. The app logs exports, imports and notarization results at info level.
- Settings are stored as separate keys in the app's preferences plist, readable with `defaults read com.karthikmac.LaunchdOps`: `LabelPrefix`, `SignPackage`, `PackageSigningIdentity`, `NotarizeAfterExport`, `SignProfile`, `ProfileSigningIdentity`. Values saved by earlier development builds are carried over.
- Settings… (⌘,) has two panes. General: Label Prefix, used by New Job to suggest labels such as `com.acme.daemon`. Signing, which applies to every job: Sign the Package (then Signing Identity, Notarize After Export and the notarization key) and Sign the Profile (then its identity). build-pkg.sh signs with the package identity; set `SIGN_IDENTITY` when running it to use another. The Export tab shows what applies, with Change in Settings…. Choices saved in a project are copied into Settings the first time.
- Renamed to LaunchdOps: app, bundle ID `com.karthikmac.LaunchdOps`, project file type `com.karthikmac.launchdops.project` (`.launchdops`), Xcode project, targets, scheme and folders, and generated script and README text. The new bundle ID gives the app a new sandbox container, so the job library and the saved notarization key start empty; `.launchops` files from before the rename no longer open.
- Jobs save automatically: no Save, Delete or Cancel prompt when closing or quitting, and every job is in the sidebar at the next launch. Each job is its own item with its own export settings; New Job… is now ⌘N, and each imported plist becomes a separate job. File ▸ Import Project… (⌘O) and Export Project… read and write `.launchdops` files (a file with several jobs is split into one job each); `.launchdops` files opened from Finder are imported. Delete Job… is undoable. LaunchdOps now has one window.
- Each setting on General, Options and Export has an ⓘ button after its label. Click it for a short description and, for launchd settings, the plist key name. Hovering over the label shows the same description.
- Validation reads program files in the payload: a program with no code signature is flagged (Apple silicon won't run it and notarization rejects it), and when the package will be signed, an ad hoc signature or a missing hardened runtime is flagged before Apple rejects the upload.
- General ▸ Program has a Choose… button. A file in your user folder or on another volume can be added to the payload in one step, with Program set to its installed path.
- The Managed Login Items profile can be signed: Export ▸ Managed Login Items Profile ▸ Signing Identity lists Developer ID Application, Apple Development and Apple Distribution identities from your keychain. With an RSA key, signed profiles stay byte-identical between exports.
- The selected job's plist XML now opens from a toolbar button or Project ▸ Show Plist XML, in a popover with Copy Plist XML. The Export tab's Selected Plist section is removed.
- Help tags on the rows of General, Options and Export say what each setting does. Session Types toggles now read Aqua (Logged-In Desktop), Background (No GUI Login), LoginWindow (Login Screen) and StandardIO (Command Line), and the Session Types and Resources footers explain that one controls where an agent loads and the other how much CPU and I/O a job gets. Plist values are unchanged.
- Stapling in the app: after Apple accepts a package notarized from LaunchdOps, the ticket is stapled to the exported `.pkg` automatically; Project ▸ Staple Package… staples a package notarized earlier. Output matches `xcrun stapler staple` byte for byte. Uses Apple's notarization ticket service (read-only lookup).
- Upgrades: renaming a job that was exported or imported adds its old label to the retired labels when you finish editing, so the next package removes the old job; renaming back removes it from the list. The project remembers exported and imported labels.
- Export ▸ Project Name and package Identifier follow the job label when left blank (the label shows as the placeholder), so a single-job export is named after its plist, for example `com.microsoft.SyncReporter-1.0.pkg`. Type a value to override. File names now keep dots.
- Fixed: uninstall.sh printed the project name unquoted; it now goes through `Shell.quoted`, and line breaks are removed from the name everywhere it is written.
- Notarization in the app: Export ▸ Package ▸ Notarization ▸ Automatically After Export, or Project ▸ Notarize Package… for an existing package. Uses your App Store Connect API key, a team key or an individual key (stored in your keychain), uploads the signed package to Apple's notary service and shows the result and Apple's log. The app now has the outgoing-network entitlement, used only for this. Progress shows on the Export tab or in the toolbar; Project ▸ Cancel Notarization stops it. The App Store and Developer ID builds are signed differently, so each may ask once for keychain access to a key saved by the other.
- Signing uses the newest unexpired identity when a renewed certificate shares its name, reports "Signing was not allowed" when you click Deny, and builds the certificate chain without network fetches. The package builder rejects `.`/`..` paths, duplicate paths and file/folder conflicts.
- Package mode can export a finished installer package (`package/<Name>-<version>.pkg`) instead of the package project and build-pkg.sh. LaunchdOps writes the xar, payload, bill of materials and distribution itself (no command-line tools, no dependencies) and signs it with a Developer ID Installer identity chosen from the keychain. The signed package can be notarized and stapled with `notarytool` and `stapler` (steps in the generated guide); Build Script output remains available. New validation: unsigned package (warning), too many files for the package writer (error).
- Copy Plist XML: Project menu, sidebar context menu and the plist popover copy the selected job's plist to the clipboard.
- Keep Alive offers "After a Crash" (`KeepAlive` with `Crashed` true) as its own choice.
- Environment Variables: Add from Text… adds several NAME=value lines at once; existing names are updated.
- Help ▸ LaunchdOps Help (⌘?) explains building, exporting, installing, testing, removing and troubleshooting.
- Calendar Schedule redesigned: each entry shows as a plain-English row (for example "Runs every day at 20:08.") and opens a popover to edit Minute, Hour, Day of Month, Weekday and Month with aligned labels. Add Custom Schedule… adds an entry and opens its editor; Add from Cron Expression… converts a cron schedule. Rows have Edit, Duplicate and Remove in a context menu.
- The New Job sheet offers User Launch Agent as a third type, matching the Type picker on the General tab.
- Add from Cron Expression… in Options ▸ Calendar Schedule turns a cron schedule (five time fields or a special string such as @daily) into calendar entries. Handles lists, ranges, steps, names and the day-or-weekday rule of crontab(5).
- New window design: sidebar grouped into Launch Daemons and Launch Agents with search and an Add/Remove bar; New Job sheet to choose daemon or agent; General, Options and Export tabs in the toolbar; validation status popover.
- Export options: choose whether to include the installer package, Managed Login Items profile, scripts, fleet verification and the deployment guide. Optional signing identity used by `build-pkg.sh`.
- Export runs off the main thread with progress; minimum window size 900 × 560; export file list preview.
- UI placement, component, visual, copy and behaviour rules for all future UI. `ChoiceRow` and `IncludeRow` moved to shared components.
- Package identifier, version and signing identity live only on the Export tab; they are separate from the launchd labels.
- Payload files are edited from the General tab; the separate Settings, Payload and inspector views are removed.
- Launch opens a new untitled project instead of the Open panel when no documents are restored.
- Fixed a build error in `ZipWriter` (`withUnsafeBytes` resolved to the `Data` method instead of the global function).
